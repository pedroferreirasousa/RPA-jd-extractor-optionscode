1. SISTEMA ATUAL (O QUE JÁ EXISTE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Arquivos do projeto:
  app/main.py       → Interface gráfica (GUI) com CustomTkinter
  app/scraper.py    → Login no site JD via Selenium + captura do Bearer Token
  app/processor.py  → Lê lista de chassis, chama a API JD e salva Excel

Fluxo atual:
  [1] Usuário clica "Fazer Login" → Abre Chrome → Faz login Okta → Token Bearer capturado
  [2] Usuário seleciona planilha .xlsx com coluna "chassi"
  [3] Para cada chassi da lista, faz GET na API:
      https://jdwarrantysystem.deere.com/api/products/{CHASSI}/options?export=EXCEL&language=EN
  [4] A API retorna um .xlsx com os dados daquele chassi
  [5] Adiciona coluna CHASSI_REFERENCIA = o chassi consultado
  [6] Concatena todos e salva como arquivo Excel final

Dados que a API retorna por chassi (colunas do Excel gerado pela API JD):
  - PIN           → Ex: 1CQS550AKN0145397
  - Code          → Ex: 6068, PTP, T3, O-0212, O-0430...
  - Description   → Ex: "6 Cyl 6.8L Engine", "Portuguese", ...
  - Created       → Ex: 2022-09-17 00:00:00
  - Created By    → Ex: A0WOWYB, PMAGALE
  - Deleted       → Ex: 2022-09-17 00:00:00 (pode ser vazio)
  - Deleted By    → Ex: A0WOWYB (pode ser vazio)
  + CHASSI_REFERENCIA → Adicionado pelo código (igual ao PIN)

OBS: PIN e CHASSI_REFERENCIA são o mesmo valor. A coluna CHASSI_REFERENCIA
     foi adicionada pelo código para rastreabilidade, mas é redundante com PIN.

3. MAPEAMENTO: DADOS EXTRAÍDOS → COLUNAS DO BANCO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Dado extraído (Excel/API JD)    →  Coluna MySQL (tb_EquipmentOptions)
  ─────────────────────────────────────────────────────────────────────────
  PIN                             →  pin
  Code                            →  code
  Description                     →  description
  Created                         →  created_at
  Created By                      →  created_by
  Deleted                         →  deleted_at        (NULL se vazio)
  Deleted By                      →  deleted_by        (NULL se vazio)
  [momento do INSERT]             →  created_at_db     (NOW() gerado pelo código)
  [momento do INSERT]             →  updated_at        (NOW() gerado pelo código)
  CHASSI_REFERENCIA               →  (não tem coluna separada — é o mesmo que pin)
  id_EquipmentOptions             →  AUTO_INCREMENT — não precisa inserir

  Observação sobre CHASSI_REFERENCIA:
    O campo pin da tabela JÁ é o chassi. A coluna CHASSI_REFERENCIA que o
    código adiciona ao Excel é redundante. No banco, o campo "pin" cobre isso.

4. EXEMPLO DO INSERT SQL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  INSERT INTO tb_EquipmentOptions
    (pin, code, description, created_at, created_by, deleted_at, deleted_by,
     created_at_db, updated_at)
  VALUES
    (%s, %s, %s, %s, %s, %s, %s, NOW(), NOW());

  Parâmetros em ordem:
    1. pin         → valor da coluna PIN do Excel
    2. code        → valor da coluna Code do Excel
    3. description → valor da coluna Description do Excel
    4. created_at  → valor da coluna Created do Excel
    5. created_by  → valor da coluna Created By do Excel
    6. deleted_at  → valor da coluna Deleted (None/NULL se vazio)
    7. deleted_by  → valor da coluna Deleted By (None/NULL se vazio)
    (created_at_db e updated_at preenchidos automaticamente com NOW())

  Estratégia de duplicatas — INSERT IGNORE ou ON DUPLICATE KEY:
    Se um chassi for processado duas vezes, pode gerar registros duplicados.
    Recomendação: usar INSERT IGNORE para pular linhas já existentes com
    o mesmo pin+code, ou usar ON DUPLICATE KEY UPDATE updated_at=NOW().
    Para isso, seria ideal criar um UNIQUE INDEX em (pin, code) no banco.

8. ESBOÇO DO CÓDIGO DA FUNÇÃO inserir_no_banco()
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  import mysql.connector
  from datetime import datetime

  DB_CONFIG = {
      "host":     "HOST_DO_SERVIDOR",
      "port":     3306,
      "user":     "USUARIO",
      "password": "SENHA",
      "database": "db_Cor_Maqnelson_RPA_Dev"
  }

  SQL = """
    INSERT INTO tb_EquipmentOptions
      (pin, code, description, created_at, created_by,
       deleted_at, deleted_by, created_at_db, updated_at)
    VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s)
    ON DUPLICATE KEY UPDATE updated_at = VALUES(updated_at)
  """
  # (ON DUPLICATE KEY só funciona se houver UNIQUE INDEX em pin+code)

  def inserir_no_banco(df):
      conn = mysql.connector.connect(**DB_CONFIG)
      cursor = conn.cursor()
      agora = datetime.now()
      inseridos = 0

      df.columns = [str(c).lower().strip() for c in df.columns]

      for _, row in df.iterrows():
          vals = (
              str(row.get("pin", ""))       or None,
              str(row.get("code", ""))      or None,
              str(row.get("description", "")) or None,
              str(row.get("created", ""))   or None,
              str(row.get("created by", "")) or None,
              str(row.get("deleted", ""))   if pd.notna(row.get("deleted")) else None,
              str(row.get("deleted by", "")) if pd.notna(row.get("deleted by")) else None,
              agora,
              agora,
          )
          cursor.execute(SQL, vals)
          inseridos += 1

      conn.commit()
      cursor.close()
      conn.close()
      return inseridos

9. OBSERVAÇÕES IMPORTANTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. UNIQUE INDEX (evitar duplicatas)
     Para que ON DUPLICATE KEY UPDATE funcione, execute no banco:
       ALTER TABLE tb_EquipmentOptions ADD UNIQUE INDEX uq_pin_code (pin, code);
     Isso garante que o mesmo chassi+opção não seja inserido duas vezes.

  2. Colunas de data (created_at, deleted_at)
     Estão mapeadas como varchar(45) no banco — então passamos como string.
     O valor vem da API como "2022-09-17 00:00:00" — ok para varchar.

  3. created_at_db vs created_at
     created_at  → data que a JD criou o registro (vem da API)
     created_at_db → data/hora que o nosso sistema inseriu no banco (agora)

  4. CHASSI_REFERENCIA
     Não tem campo separado no banco — o PIN já é o chassi.
     Podemos ignorar essa coluna extra na hora do INSERT.

  5. Segurança das credenciais
     Nunca hardcodar senha no código versionado.
     Opções: arquivo .env + python-dotenv, ou variável de ambiente.

  6. Compatibilidade com o .exe
     mysql-connector-python precisa ser incluído no pyinstaller.
     Adicionar ao main.spec na seção hiddenimports se necessário.
